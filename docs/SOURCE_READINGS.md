# Reviewing PDF and OCR readings

In **Explore**, select a document and choose **Review PDF / image reading**. The dialog shows the original page beside its extracted text. Use **Zoom page** for small print; page navigation keeps each review attached to its own page or image frame.

A reading starts unreviewed, including text extracted directly from a PDF. Embedded text may itself have come from earlier OCR. Newly processed OCR retains Tesseract TXT/TSV output, word offsets, image coordinates, raw scores, language and engine metadata. Parser identity is retained in the extraction artifact. Low or missing scores provide review hints, not accuracy probabilities. Older extractions remain readable and reviewable with explicitly unavailable word scores; re-extraction is needed to collect new metadata.

Enter a reviewer name and reason and compare the page before confirming, correcting or marking its reading unreadable. Names are self-reported within the authenticated local workspace, not independently verified identities. Original bytes, canonical text and original quotations never change. Reviews are append-only records in the private workspace file `source-reading-reviews.sqlite3`; preserve this file alongside the workspace when backing up. They bind the original blob, extraction artifact, document, page/frame and text range. A newer extraction does not silently inherit a prior review.

Claim interpretation is reviewed separately. Accepting an interpretation requires a confirmed original reading. Confirmation means the reviewer checked the transcription, and acceptance means the interpretation matches that transcription; neither establishes that an event occurred or that a statement is true. Corrections and unreadable readings mark dependent original claims for reassessment. Rejected or unresolved interpretations may be recorded against the updated reading. Supported claims recomputed from corrected text are shown as unreviewed candidates with correction-relative offsets, never passed off as quotations from the original extraction.

The current knowledge HTTP view overlays these review states. Newly captured research snapshots retain review records alongside unchanged passages. Existing investigations and immutable graph snapshots remain frozen; no historical answer is silently rewritten. The ordinary retrieval index still searches original extracted text. Recomputed correction candidates can be accepted, rejected or left unresolved separately; their reviews retain the corrected quote and reading revision. Corrected-text full-text indexing and automatic replacement of frozen graph nodes are not implemented in this first workflow. A poor or empty reading is never evidence that the source lacks relevant information.

Review routes use Graf's existing authentication, same-origin protections and source-publication checks. Concurrent reviews require the current previous-review ID. If a publication changes during saving, the review transaction rolls back. Page images come from hash-verified artifacts or bounded local rendering of the captured PDF, with private temporary files and no-store responses. Original documents and live scans are not modified by opening a review.

The UI supports page-level correction up to 16,000 characters and shows the first 100 low-score word hints, with explicit overflow text. Raw score below 60 is only a triage heuristic, not a validated error threshold. Tables, handwriting, reading order, and high-scoring mistakes still require visual judgment. OCR language data must be installed for the configured language. No external OCR service, translation, automatic spelling correction, or model billing is introduced.
